## 4. Board update procedure

1. Open the existing GitHub Project #4 and retain all Sprint 1 cards/history.
2. Use a Sprint/Iteration or label filter to distinguish Sprint 2 from Sprint 1; do not delete Sprint 1 records.
3. Check whether each planned task already has an Issue before creating any new one.
4. For #28, #29, #30 and #31, update/link existing Issues only.
5. For remaining tasks, record real Issue URL/number, assignee and status after verification.
6. Move an item to In Review only when its PR/deliverable is ready; mark Done only after reviewer acceptance.
